## コンセプト詳細

### 競合との差別化ポイント

Beads Creator（160万DL）が王者だが、以下の隙間を狙う：

1. **広告なし** → Beads Creatorはインタースティシャル広告がウザいとレビューで不満多数。beadotは広告ゼロ
2. **カメラ直結フロー** → 起動→撮影→即変換。Beads Creatorは図案作成画面からの写真インポートでワンステップ多い
3. **変換精度（CIEDE2000 + Floyd-Steinbergディザリング）** → Lab色空間でのCIEDE2000最近傍マッピングに加え、Floyd-Steinberg誤差拡散法でグラデーションを自然に表現。前処理（ぼかし・コントラスト・彩度補正）と後処理（孤立ピクセル除去）で図案品質を最大化。Beads Creatorにはディザリング機能なし
4. **買い物リスト** → 必要ビーズの色名・個数リストをPDF/テキストで出力。買い物時にそのまま使える
5. **実寸PDF** → プレートの下に敷いてそのまま作れるPDF出力
6. **六角形・ハート・星型プレート対応** → 四角形だけでなく、パーラービーズの全プレート形状に対応（六角形はオフセットグリッドで図案生成）
7. **使用色数コントロール** → スライダーで色数を調整可能。「12色だけで作りたい」を実現
8. **白黒ミニマルUI** → mamonis統一美学。ごちゃつかない

### このアプリが「塗り絵」ではない理由

numpixは「画面上で塗って遊ぶ」体験。beadotは「図案を見て実物を作る」体験。出力先がデジタル（numpix）とフィジカル（beadot）で完全に異なる。画面上の塗り絵機能は不要。代わりに図案表示・PDF出力・買い物リストに全振りする。

## 画面構成・フロー

### アプリ起動フロー

```
起動 → カメラ起動（初回は権限許可ダイアログ）
         ├─ 撮影ボタン → 設定選択 → クロップ画面（選んだ形状のマスク表示）→ 変換 → 図案画面
         ├─ ギャラリーボタン（左下） → 写真選択 → 設定選択 → クロップ画面 → 変換 → 図案画面
         └─ 作品一覧ボタン（左下上） → 保存済み図案一覧
```

**ポイント: 設定選択→クロップの順序にする理由**
プレート形状（四角/六角/ハート等）やサイズ（S/L/2L）によってクロップのアスペクト比やマスク形状が変わる。先に設定を決めてからクロップすることで、ユーザーは選んだプレートに合った構図で写真を切り取れる。

**六角形プレート対応の技術的ポイント:**
六角形プレートは突起がオフセット配列（偶数行と奇数行で半ビーズ分ずれる）。これは四角形グリッドとは根本的に異なるため:
1. 図案生成時にオフセットグリッドとして計算
2. CustomPainterで丸ビーズを千鳥配置で描画
3. PDF出力も千鳥配置で生成
4. 実寸PDFのセル位置も千鳥配置に対応

## 変換アルゴリズム

### 概要：Beads Creatorを精度で叩く

Beads Creatorの弱点は「変換精度が低い」「色がくすむ」「白っぽくなる」。これを完全に上回るために、以下の3段階パイプラインを実装する。特に **Floyd-Steinbergディザリング** は、競合のPixel Beads（2025年末に導入）が採用した最新手法。ビーズという限られたパレットでグラデーションを表現するために不可欠。

### ビーズ図案変換パイプライン

```
入力画像
  ── STEP 1: 前処理 ──
  → 正方形クロップ（中央基準。長方形プレートの場合はアスペクト比に合わせてクロップ）
  → ピンチ操作でクロップ範囲を調整可能（UIで実装済み想定）
  → 軽度ガウシアンぼかし（σ=0.5〜1.0）を適用してノイズ除去
      ※写真のノイズがビーズ1個分の色に影響するのを防ぐ
  → コントラスト自動調整（ヒストグラム伸長）
      ※暗い写真・白飛び写真でもまともな図案が出るように

  ── STEP 2: リサイズ ──
  → リサイズ（選択したプレートサイズ: 15×15 〜 128×128）
  → 補間方式: Area補間（OpenCV INTER_AREA相当）
      ※バイリニアではなくArea補間。縮小時にピクセル情報を平均化するため
        色情報のロスが最小。ビーズ図案は必ず縮小処理なのでArea一択

  ── STEP 3: パレットマッピング ──
  → ディザリングモード選択（ユーザー設定）:
      A) ダイレクトマッピング（デフォルト）
         各ピクセルをCIEDE2000最近傍で直接マッピング
      B) Floyd-Steinbergディザリング
         誤差拡散法で隣接ピクセルに量子化誤差を分配
  → 使用色数が多すぎる場合の最適化（後述）

  ── STEP 4: 後処理・出力 ──
  → 孤立ピクセル除去（3×3近傍で自分だけ違う色→周囲の最頻色に置換）
      ※ノイズ的に1ビーズだけ違う色が散らばるのを防止
  → 図案データ生成（各セルのビーズ色ID）
  → 買い物リスト生成（色ID → 個数の集計）
  → SQLiteに保存
```

### CIEDE2000色差計算（コア技術）

| 項目 | 仕様 |
|:---|:---|
| 方式 | 固定パレットへのCIEDE2000最近傍マッピング（k-meansは使わない） |
| 理由 | ビーズは実在する固定色。k-meansで自由な色を生成しても意味がない。パレットの中から知覚的に最も近い色を選ぶ |
| 色差式 | CIEDE2000（ΔE00）。CIE94やユークリッド距離ではなく、人間の知覚に最も近い色差式を採用 |
| 参考実装 | michel-leonard/ciede2000-color-matching（GitHub、40+言語対応、10億色ペアテスト済み、パブリックドメイン） |
| Dart実装 | 約80行。kL=kC=kH=1（標準パラメータ）。Sharma論文のテストデータで検証 |
| RGB→Lab変換 | RGB → sRGBリニア化（ガンマ補正除去）→ XYZ（D65白色点）→ Lab。ビーズ色のLab値はビルド時に事前計算してJSONに含める |
| 処理 | Isolateで実行（UIブロック防止） |

### Floyd-Steinbergディザリング（差別化の切り札）

| 項目 | 仕様 |
|:---|:---|
| 概要 | 量子化誤差（元の色とマッピング先ビーズ色の差）を隣接ピクセルに拡散し、限られたパレットでも滑らかなグラデーションを知覚させる |
| 拡散係数 | Floyd-Steinberg標準: 右 7/16、左下 3/16、下 5/16、右下 1/16 |
| 色空間 | Lab色空間で誤差計算・拡散（RGBチャンネル独立処理は色にじみが出るため不可。Labベクトル量子化方式を採用） |
| 拡散強度 | ユーザー調整可能なスライダー（0%〜100%）。0%=ダイレクトマッピング、100%=フルFloyd-Steinberg。50%がデフォルト推奨 |
| 効果 | 肌のグラデーション、空のグラデーション等で劇的に品質が向上。ビーズ50色しかなくても、目の錯覚でより多くの色があるように見える |
| 注意 | 15×15等の小サイズでは効果が薄い（ピクセル数が少なすぎてディザパターンが見える）。29×29以上で推奨。UIで「小サイズではダイレクトマッピング推奨」のヒントを表示 |
| 競合優位 | Beads Creatorにはディザリング機能なし。Pixel Beadsは2025年末に導入済みだがWebツール。モバイルアプリで実装すればモバイル初 |

### 使用色数の最適化

| 項目 | 仕様 |
|:---|:---|
| 問題 | パレット全色から最近傍マッピングすると使用色が多くなりがち（パーラー57色で30色以上使う場合も）。ビーズを揃えるのが大変 |
| 解決策1 | 変換後に使用色数をチェック。使用面積が少ない色（全体の1%未満）は、CIEDE2000で次に近いビーズ色に置き換え |
| 解決策2 | 「使用色数上限」スライダー（v1から実装。5〜50色、デフォルト: プレートサイズ依存） |
| 最適化アルゴリズム | 1. 全使用色を面積降順ソート → 2. 上限を超える色を下位から順に、最もΔE00が小さい上位色に統合 → 3. 統合後の図案を再生成 |
| 目標色数 | プレートサイズに応じた推奨デフォルト: 15×15→8〜12色、29×29→12〜20色、58×58→20〜35色、128×128→30〜50色 |
| UI表示 | 設定選択画面: スライダー横に「XX色」と現在値表示。図案画面: メニューに「色数調整」追加→スライダー変更で即座に図案を再計算・プレビュー更新（Isolateで再変換、パレットマッピング＋後処理のみ再実行するため高速） |

### 前処理の詳細

| 処理 | 仕様 | 理由 |
|:---|:---|:---|
| ガウシアンぼかし | σ=0.5（デフォルト）、ユーザー調整不要 | 写真のセンサーノイズ・圧縮アーティファクトがビーズ1個の色に影響するのを防ぐ。軽度なので元画像の印象は変わらない |
| コントラスト自動調整 | ヒストグラムの上下5%をクリップ後に0-255へ伸長 | 暗い室内写真や白飛び写真でもコントラストが確保され、ビーズの色分けが明確になる |
| 彩度ブースト | 彩度を10%強調（HSL空間でSチャンネルを1.1倍） | ビーズは物理素材なので画面より彩度が低い。事前に彩度を少し上げておくと完成品が元画像に近づく |

### 孤立ピクセル除去（後処理）

| 項目 | 仕様 |
|:---|:---|
| 目的 | 「1ビーズだけ違う色がポツンとある」状態を除去。実際に作ると目立って汚く見えるため |
| アルゴリズム | 各セルの3×3近傍を走査。8隣接中、自分と同じ色が0個の場合、8隣接の最頻色に置き換え |
| ON/OFF | ユーザー設定で切り替え可能（デフォルトON）。ドット絵風の意図的な単色配置を残したい場合はOFF |
